The chat widget's server (M4-02, M4-03, M4-04, M4-10, and the server side of M4-06 to M4-08). Visitors get a server-issued id and secret, stored hashed, and see only the conversations they opened; an email typed into the pre-chat form is shown to agents as unverified and never opens history. A brand can let its site sign the signed-in user (HMAC-SHA256, five-minute window) to continue that user's widget conversations on any device, and optionally show their other channels read-only. Every widget route and the new `/widget` Socket.IO namespace check the brand's allowed origins and per-address and per-visitor throttles, with an optional Turnstile or hCaptcha challenge before the first message. Messages carry a client id and a per-conversation `seq`, so retries never duplicate and a client catches up with `?after=`; an SSE stream stands in when WebSockets are blocked, and agent replies, typing, presence and queue position reach the widget live. Admins and Team Leaders configure it all under Channels › Widget, including a transcript-by-email option sent from the brand's own address. The protocol is documented for native apps in `docs/guides/widget-protocol.md`.
