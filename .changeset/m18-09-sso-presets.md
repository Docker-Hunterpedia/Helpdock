SSO presets (M18-09): a new OpenID Connect connection can start from Google Workspace (OIDC) or Microsoft Entra ID (OIDC). The preset fills the issuer (or the Entra `{tenant-id}` template, which the form and the API refuse to save unreplaced), the email, name and groups claims, and hints for the email domains, and links to its section of the SSO guide. Later edits stay; nothing about the preset is saved. Because Entra ID sends no `email_verified`, an OIDC first link now also accepts Entra's `xms_edov: true` on the `email` claim, but only from a tenant member (`acct` 0, never a guest) and only when the connection's issuer names one tenant by GUID in the global cloud (`https://login.microsoftonline.com/<tenant>/v2.0`, never `common`, `organizations`, `consumers` or the personal-account tenant) and the token's `iss` and `tid` match it. **Note for operators:** an Entra app registration used for OIDC must add the `email`, `xms_edov` and `acct` optional claims. An existing Entra OIDC connection whose tokens already carry `xms_edov` and `acct` starts linking by email, and creating accounts when "Create accounts on first sign-in" is on, at the next sign-in after this upgrade: review its Email domains, that setting and Entra's "Assignment required" before upgrading. A Google Workspace connection must use the Internal user type (see the SSO guide).
