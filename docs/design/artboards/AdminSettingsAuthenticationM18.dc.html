Admin/Settings-Authentication

  • Amends Admin/Settings › Authentication. Install admins only. Cards in this order: Sign-in methods, Passkeys, Google, Microsoft, GitHub (unchanged), with the Redirect URLs aside gaining Microsoft.
  • “Require a second factor” replaces “Require two-factor authentication”: either an authenticator app or a passkey satisfies it.
  • Passkeys card: StatusBadge (Available, Paused, Unavailable); the pinned RP ID read-only in mono; a usage count. Nothing to configure in the normal case.
  • Drift (passkeys-rp-changed): the warning Banner names both hosts in bdi dir=ltr. “Move passkeys to …” opens a confirm dialog saying every existing passkey stops working; it re-pins auth.webauthn.rpId, is audited, and emails every staff member who had one. The same Banner shows on the System page.
  • Google: “Allowed Workspace domains” is a tag input for oauth.google.allowedDomains (lower-cased, no @). A non-empty list refuses @gmail.com.
  • Microsoft: tenant ID required and validated as a GUID; client secret write-only with Replace; the personal-accounts checkbox maps to oauth.microsoft.allowConsumers, off by default (D-52).
  • Any of these pinned by an HD_* key shows the existing “Set by environment” lock and is read-only.
