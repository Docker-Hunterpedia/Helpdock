Admin/Me-SignInProviders

1.0.2 follow-up to the 1.0.1 OAuth binding fix (ADR 0051). A card on /me/security, after Two-factor and before Sessions, in the existing Card shape (Admin/Settings).

  • One row per provider the install has configured (Google, GitHub; Microsoft joins in M18). Not configured: not listed. None configured: card not drawn.
  • Row: 32 px icon tile, name, Connected StatusBadge (success), caption with the linked account's email in bdi and the date; outlined "Disconnect <provider>" or primary "Connect <provider>". Button names include the provider.
  • Connect / Disconnect open the step-up dialog (password or TOTP code; same rate limit as today), then Connect redirects to the provider and back to this page with a success toast, or the callback error screen (oauth-link-required, oauth-identity-conflict).
  • Warning notice shows only while the person has no provider linked and a provider is configured; it explains the 1.0.1 change. Hidden once any provider is linked.
  • Disconnect is refused for the last way to sign in (no password and no other provider): button disabled with a caption saying why.
  • Arabic: mirrored; provider names stay Latin; emails in bdi.
