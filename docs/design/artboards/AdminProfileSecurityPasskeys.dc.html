Admin/Profile-Security-Passkeys

  • A new card on /me/security, after Two-factor and before Sign-in methods. Card shape from Admin/Settings; rows from Admin/Me-SignInProviders (no new component: PasskeyRow is not needed).
  • Row: 32 px KeyRound tile; name in bdi; a “Synced” Tag (Lucide Cloud) when the backup-state flag is set; added date and last used; ghost Rename and outlined Remove, both naming the passkey in aria-label.
  • Add, rename and remove each open the step-up dialog first (passkey, password or TOTP; one shared 5-per-15-minutes budget), then their own dialog. Success shows a toast and sends the securityChange email.
  • Add: the browser prompt, then the name step from Admin/Enrol2FA-Choose. The 10-passkey limit replaces the prompt with the limit dialog.
  • Remove is refused when it would leave an account that must have a second factor with none (second-factor-required): the button is disabled and the caption says why.
  • Remove confirmation is a destructive dialog that says what else still protects the account.
  • Empty state: an EmptyState in the card with one sentence; the primary Add button stays in the header.
  • Dates in the app's locale; Arabic mirrored; names in bdi.
