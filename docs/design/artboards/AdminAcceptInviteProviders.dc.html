Admin/AcceptInvite-Providers

  • Amends Admin/AcceptInvite (M18-07). Configured providers appear above the password field as a second way to accept. Choosing one runs the provider sign-in and, because the invite token already proved the mailbox, binds that provider identity to the new account (DOMAIN-RULES §12 “sets password or OAuth link”).
  • The provider account must be for the invited address: Google and Microsoft by their verified email, GitHub by any verified email on the account that equals the invited one. Otherwise the mismatch state; nothing is created.
  • An account accepted through a provider has no password; it can add one later. Passkeys are added after acceptance, not here (D-54).
  • The second-factor step follows as today when the install requires it.
  • Arabic: mirrored; emails in bdi dir=ltr; provider names stay Latin.
