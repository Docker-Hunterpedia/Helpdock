M14-30 · the list toggle button

  • Why. [ hides the ticket list, but nothing on screen says so. Support staff who do not use shortcuts need a button.
  • Where. A 32 px icon button at the inline start of the ticket header, before the reference, on the split layout only (1024 px and wider, a ticket open). Lucide panel-left-close while the list shows and panel-left-open while it is hidden; mirrored in Arabic.
  • Name. Named “Hide the ticket list” while the list shows and “Show the ticket list” while it is hidden. The name carries the state, so there is no aria-pressed (amended after review, 2026-11-24). Tooltip with the name and the [ key, aria-keyshortcuts="[". It keeps focus when pressed, and after j or k moves to another ticket.
  • Replaces. The full-width “Show the ticket list” row above a ticket whose list is hidden goes; the same button brings the list back, so the thread gains that row too.
  • With no ticket open the list always shows and [ does nothing; a hidden list comes back when the ticket closes (amended after review). Below 1024 px there is no second column and no button.

M14-31 · reply to one message

  • What. Each public message a customer sent by email has a small Reply button at the inline end of its header line. It is always visible (not hover only), 24 px high with a 32 px hit area. Notes, staff replies, system events and messages from chat channels have none.
  • Pressing it. Opens the composer on the Reply tab, moves focus into the text, and puts a “Replying to Mona Khalil’s email of Tue 12:05” strip above the text. The message it answers gets the accent outline while the strip shows. Pressing Reply on another message moves the strip; the × or the Internal note tab clears it. The draft text is never touched.
  • The quote. “Show quote” opens the quoted message read-only inside the strip. The quote is added by the server under the reply, with a line “On <date> UTC, <name> wrote:” in the customer’s language. Agents cannot edit it. Quoted text is the message’s plain text, capped at 2,000 characters; attachments are not re-sent.
  • The email. In-Reply-To is that message’s Message-ID, and References is its chain plus that id, so mail clients file the reply under the email it answers. To, Cc and From are the ticket’s, as for any reply (amended after review, 2026-11-24: they do not follow the chosen email). When the chosen email’s sender is not the reply’s To, the strip adds a warning line: “This quotes Omar’s email to everyone on the reply: To Mona Khalil and Cc 2.”
  • Afterwards. The sent reply shows “In reply to Mona Khalil · Tue 12:05” above its bubble; pressing it scrolls to that message and focuses it. An ordinary reply (no strip) behaves exactly as today and threads to the latest message.
  • Refused. The api refuses a target that is not a public inbound email message of the same ticket (400), and one the agent cannot read (404, as for the ticket). If the message was deleted or erased before Send, the reply is not sent and the strip shows “That message is no longer available”.
  • Keyboard and screen readers. The button is in the tab order after the message; its name includes the sender. The strip is announced once (“Replying to …”) through the composer’s live region. No new single-key shortcut.
  • Not in this deliverable. Hiding the composer until the end of the thread (decided against on 2026-11-24), native reply-to on WhatsApp, Telegram, Messenger and Instagram, and replying to several messages at once.
